# DLR mapped profile integration

`createDlrProfile({project, sampleSurfaceY, verticalExaggeration:5})` installs a synchronous bundled-data adapter. `project(lat,lon)` returns canonical `{x,z}`; `sampleSurfaceY({x,z})` returns canonical terrain Y or `null` while terrain is unavailable. Initial unavailable terrain uses an explicitly marked zero placeholder (`terrainPending:true`), never a claimed ground measurement. Refresh when terrain loads.

The source has 523 active/crossover ways, 3,365 nodes, 98 mapped platform stop positions, 45 TfL stations and 47 adjacent station pairs. Named OSM platform positions avoid classifying Greenwich, Devons Road and Bow Church by their TfL entrance beside a tunnel. Stratford and Canning Town have separate platform groups; branch routing chooses a continuous sequence of actual connected platform nodes. Original TfL coordinates remain in source metadata. Woolwich Arsenal has no named stop-position node in this snapshot: its anchor is explicitly approximate, the nearest mapped tunnel node to the retained TfL point. Its documented tunnel classification is preserved.

## API

- `buildBranch({points:stopPoints, structureScale:1})` returns `{points,stationPoints,stationUs,stationIndices,terrainPending}`. Points are actual `THREE.Vector3` objects. Only actual stops have `stationId`/`id`. Every point has `_dlrProfile.nodeIndex`, classification, signed `groundRelativeM`, `depthM`, `heightM`, `surveyed:false`, `sourceWayIds`, `needsShaft` and `_depthM = -groundRelativeM`. Rail edges are subdivided to at most 20 m. Supplied stops require known TfL IDs; missing topology throws instead of drawing an invented chord.
- `station({id,nodeIndex?,structureScale:1})` returns the matching platform Vector3. Use branch `stationPoints`, deduplicated by stationId plus nodeIndex, to place markers on the actual platform used. A single coordinate per TfL station cannot represent Stratford's two separate DLR platform groups.
- `refresh({structureScale:1})` recomputes the shared network heights from terrain. `resnap(points,{structureScale:1,refreshTerrain:true})` refreshes and updates vectors in place using their node metadata. For several branches, call refresh once, then resnap with `refreshTerrain:false`. Keep metadata when cloning vectors: ordinary `Vector3.clone()` does not copy custom properties.
- `sample({x,z,nodeIndex?,structureScale:1})` returns a Vector3 with profile metadata, or null outside the mapped network. Retained nodeIndex gives exact platform/track agreement at stacked crossings; nearest X/Z is for pointer hover, not resnapping a known branch.

Structure scale is the existing normalised ratio, 0.2 for the UI's 1x and 1 for 5x. Positive modelled clearances follow this ratio, with a one-physical-metre casing clearance for surface rail; negative tunnel/cutting values remain unchanged. Master height is applied only by the global camera controller. The shared network, rather than each branch independently, determines heights, so coincident branch nodes have identical Y.

Tunnel and cutting depths ramp from actual mapped shared boundary nodes along the rail graph. Maximum tunnel depth 30 m, cutting depth 3 m, elevated clearance 8 m and embankment 3 m are illustrative model values, not surveyed heights. Short underpasses have proportionately shallow profiles. Aboveground heights use a minimal terrain-clearing envelope with an illustrative 8% physical grade; positive offsets taper into mapped portals. This cannot remove roof contamination in the underlying DSM outside the separately validated Stratford DTM patch. Do not present these computed clearances as real surveyed deck heights.

## Required production paths

1. DLR must bypass `depthForStation`'s generic 18 m fallback and generic station-depth interpolation. Build its centreline from this adapter before offset curves, meshes and train routes. Use returned stationUs, not every densified point as a stop.
2. On terrain load or Structure changes, refresh/resnap DLR points and rebuild both track curves and train curves from those same vectors. Preserve station IDs/node metadata. Recalculate curve station parameters from the retained stationIndices when vertical geometry changes. Do not inject generic river-depth points into DLR: mapped tunnels own those transitions.
3. Build DLR station markers from returned stationPoints; source lat/lon can remain in labels/metadata. For hovering, show “Elevated”, “Surface”, “Cutting” or “Tunnel”, with any numeric height labelled modelled. `_depthM` is signed and must not be clamped before geometry placement.
4. Exclude DLR from legacy `public/data/dlr/shafts.json`; its generic 6 m shafts conflict with both actual viaducts and tunnels. Only `needsShaft` may produce a tunnel access visual, with its base from the same adapter. These remain schematic access indicators, not surveyed shaft positions.
5. Existing Tube depth logic and all other lines remain unchanged. New DLR metadata must survive terrain snapping, late load, visibility toggles, train route rebuilding, pause and speed controls.

## Sources and reproducibility

The retained Overpass body/geometry snapshot and stop-position response are in project `Working/city-tranche-12Sep26s/dlr/`. Rebuild with `node scripts/prepare-dlr-profile.mjs --source /absolute/path/osm-light-rail.json`; sibling `osm-stop-positions.json` is required. Source hashes, timestamp, original tags and way IDs are bundled. The script excludes sidings/yards, keeps mapped crossovers and connects only shared OSM node identities. Original OSM “Route guessed” / “interpolation” notes are retained for underground alignments. A source way tagged both bridge and tunnel (655780510) is classified as a covered viaduct because it also carries bridge=viaduct and layer=1; this explicit conflict is retained.

[Official TfL tunnel map](https://tfl.gov.uk/cdn/static/cms/documents/tube-map-with-tunnels.pdf) independently identifies tunnelled network sections. [TfL's Woolwich construction announcement](https://tfl.gov.uk/info-for/media/press-releases/2006/april/mayor-launches-tunnelling-of-dlr-woolwich-arsenal-extension) establishes the Thames tunnel, with excavation up to 35 m beneath the river; this does not establish station depth. [TfL's 2006 board papers](https://www.tfl.gov.uk/cdn/static/cms/documents/Agenda-and-Papers-May-2006.pdf) and [operational report](https://content.tfl.gov.uk/Item05-Operational-Financial-Performance-Reports.pdf) identify viaduct strengthening for the Blackwall/East India package. [TfL Royal Docks guidance](https://tfl.gov.uk/cdn/static/cms/documents/royal-docks-ltdg-sec1-2.pdf) provides context for the Beckton branch and its underpasses. Geometry attribution: © OpenStreetMap contributors, ODbL 1.0.

Validation: four browser-free Playwright tests pass, covering all 26 TfL branches, mapped station classes, dense connected routes, real stop counts, both directions, platform alignment, terrain arrival, Structure roundtrips, subsurface invariance, aboveground grade taper, short underpasses and mapped portals. Production integration, actual train/hover/shaft behaviour and rendered acceptance remain independent checks.
