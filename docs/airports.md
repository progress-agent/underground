# Airport landmarks

Nine airports and larger airfields are included: Heathrow, London City, Biggin Hill, RAF Northolt, Elstree, Denham, Stapleford, Kenley and Damyns Hall. The list follows physical scale and current aviation activity, including established training campuses. Aircraft are illustrative static traffic, never a live feed.

The final inside-ring completeness check also examined London Colney, Titsey, Rushett Farm, Gerpins Farm, Jenkins Farm and NPAS Lippitts Hill. London Colney is a small club strip: its [operator lists325m and265m runways, no fuel or clubhouse facilities](https://hertsmicrolightclub.co.uk/airfield/) and no training. Titsey, Rushett, Gerpins and Jenkins are private strips; NPAS is helicopter-only. These are excluded by scale/use, never by a blanket microlight category. Fairoaks, Redhill, North Weald, Gatwick, Luton, Stansted and Southend lie outside M25. Disused airfields are excluded.

## Integration contract

```js
import {createAirports, isAirportBuilding, getAirportHoverInfo, AIRPORT_DATA} from './airports.js';
const airports = createAirports({getSurfaceY:getTerrainMeshSurfaceY, VE:5, heightScale:getBuildingHeightScale()});
scene.add(airports);
// The Structure control:
airports.userData.setHeightScale(getBuildingHeightScale());
// Only when canonical terrain changes, not for a master-height parent transform:
airports.userData.refreshTerrain();
```

Coordinates are canonical British National Grid metres relative to proj4's projection of WGS84 51.5074,-0.1278, matching main.js `llToXZ` at horizontalScale=1. No fixed 530000/180400 origin is used. `getSurfaceY({x,z})` supplies canonical pre-master scene Y, already exaggerated by terrain VE. Airport geometry has no master multiplier. Register its meshes in the master's existing canonical-world mechanism. It has no tick/update or simulation dependency.

Architecture starts in real metres and scales once by VE×Structure about each object's terrain sample. Pavement remains terrain-draped regardless of Structure, subdivided to maximum 30m triangle edge. Static aircraft have separate sampled anchors and retain their landing-gear offset. `refreshTerrain` updates bases and surface lifts, then reapplies current Structure. Resources are merged by material per airport: the nine-site construction has95 draw calls and823488 vertices,89 buildings,17 runway strips and183 static aircraft, including8 Kenley gliders and3 Heathrow queued jets. No instance colours or per-aircraft scene objects. `dispose()` releases geometry/materials and detaches the group.

**Initialisation order/fallback:** initialise airports after terrain succeeds, before creating buildings. Activate building suppression only after `createAirports` succeeds and the group is attached. Keep this group through live/baked building swaps. Missing/invalid terrain throws; catch at caller, show the normal generic buildings, report airport failure. Data is a bundled JSON import, so no independent fetch can succeed with HTML. Caller must never enable suppression if construction failed.

**Suppression:** `isAirportBuilding({x,z,cx,cz,osmId,footprint})` tests only the 89 replaced source footprints, with an 8m local guard for the point-mapped control tower. `cx/cz` are accepted because existing surface tiles use them. It does not remove a whole airport neighbourhood. Feed it building centres and, when available, original footprints; no source OSM ID is required because the tiles omit IDs. Apply in live `createTileBuildings`, the baked-building writer, and retained landmark-neighbour restoration if relevant. Root owns those files and must regenerate baked assets after this integration. The bake must record enough compatibility state for callers to reject a suppression-baked payload if airports failed to initialise; otherwise the generic fallback would contain holes. Baked airport exclusion must not activate without its companion airport module/version. Existing baked files do not yet contain this exclusion.

**Hover:** every mesh has `userData.type='airport'`, `airportId`, `name`, `part`. `userData.pickables` returns all airport meshes. Since architecture is merged, pass the actual ray intersection's `faceIndex` to `getAirportHoverInfo(mesh,faceIndex)`. It returns the exact terminal/hangar/tower/aircraft name when hit, otherwise the airport name. Feature ranges are nonindexed vertex ranges in `mesh.userData.features`. Current airport picker signature discards faceIndex, so integration must retain it. Only the independently supported Heathrow tower 87m and City's digital mast 50m return `heightM`. No guessed roof heights or airport dates are shown as terminal facts. All other optional fact fields are absent. Root owns hover type/formatting integration and should use existing app typography/palette.

Diagnostics: `userData.stats`, each airport group's `userData.aircraft` (position, yaw, metres length, state and OSM source), and `userData.runways`. The three waiting jets are on mapped Taxiway S beside Heathrow's eastern 27L access, outside the active runway.

## Source and modelling record

`src/airport-data.json` preserves source OSM IDs, projected geometry, heights and whether each height was sourced or illustrative. `scripts/prepare-airports.mjs <source-directory>` deterministically rebuilds from `*-osm.json` archived in the project evidence directory. OSM data is ODbL, attribution is © OpenStreetMap contributors. Preserve/add this to the app's existing attribution surface. Source snapshots carry original Overpass timestamps; no airport network request runs in the client.

Heathrow uses its two mapped runways, terminal groups T2A/T2B, T3 and Pier 6, T4, T5/T5B/T5C, hangars and the central tower. Main T3 is relation18911624. Stale OSM Terminal1 is deliberately excluded because the operator lists four current terminals. Campus wrapper relations for T2 and T5 are excluded to prevent a second copy of their component buildings. Roof ribs, curtain-wall mullions, floor bands and hangar doors follow the footprints' principal bearings. T5 and T2 have shaped segmented roofs. Secondary building heights, façade details, roof profiles and aircraft sizes are authored simplifications, explicitly marked as such, rather than fabrication of survey data. Light airfields have straight-wing propeller aircraft; business/military fields have smaller jets; Heathrow has narrow/wide-body silhouettes with wings, tailplanes, fins, turbofans, cockpit and landing gear.

The operator's [Heathrow airfield map](https://www.heathrow.com/content/dam/heathrow/web/common/documents/company/team-heathrow/airside/airfield-maps/Heathrow_Maintenance_Block_Map_V50_A3_v10.pdf) establishes runway/terminal/taxiway relationships and published runway dimensions. Adjacent OSM displaced-threshold ways are merged into full Heathrow/City pavement. At Northolt the [current military AIP, AIRAC09/26, AD2.12](https://www.aidu.mod.uk/aip/pdf/ad/EGWU-Northolt-Combined.pdf) specifies 1683×40m and a92m displaced07threshold: the missing southwestern92m is included, preserving mapped threshold positions. This supersedes older1687×46m secondary summaries. At Biggin Hill the mapped threshold line is extended southwest along its bearing to the [operator's1806m resurfaced runway](https://bigginhillairport.com/operations/runway-resurfacing/); the completion is identified as authored from the published physical length. Elstree's extra overrun ways and Stapleford's grass overrun are not counted as paved runway. Source-derived outlines are illustrative map geometry, not an aeronautical navigation product.

Primary architectural references: [Heathrow's current terminal relationships](https://www.heathrow.com/company/heathrow-fan-zone/where-is-everything-located-at-heathrow), [RSHP Terminal5 design](https://rshp.com/projects/transport/terminal-5-heathrow-airport/), [RSHP87m control tower](https://rshp.com/projects/transport/air-traffic-control-tower-heathrow/), [SESAR's account of City's 50m digital mast](https://www.sesarju.eu/news/london-city-airport-wins-2022-sesar-3-ju-aci-europe-digital-transformation-award). [London City NATS AIP supplement](https://www.aurora.nats.co.uk/htmlAIP/Publications/2023-06-01/html/eSUP/EG-eSUP-2023-036-en-GB.html) gives1508×30m.

Primary inclusion/purpose references: [RAF Northolt's military and civilian role](https://www.raf.mod.uk/our-organisation/stations/raf-northolt/), [Elstree operator, explicitly within M25](https://www.londonelstree.com/visitors), [Denham operator, explicitly inside M25](https://egld.com/contact.html), [Denham pilot information and two runway directions](https://www.egld.com/pilots.html), [Stapleford operator pilot briefing and campus layout](https://flysfc.com/wp-content/uploads/2026/07/STAPLEFORD-AERODROME-PILOT-BRIEF-v1-2026.pdf), [Stapleford flight training operation](https://flysfc.com/), [Biggin Hill current operation and location](https://bigginhillairport.com/).

## Verification and remaining integration

Seven Node-only Playwright tests exercise source coverage, finite merged geometry, static parking/queue positions, scaling/terrain roundtrips, bounded suppression, exact-feature hover facts, and missing-terrain failure. They require no browser/GPU. Visual acceptance remains an integrator/evaluator responsibility: overhead and oblique Heathrow, all nine airports, 1x/5x Structure and low/high Master, a same-pose GPU performance comparison, and live/baked suppression.

The former coarse M25 ring placed Stapleford outside incorrectly. The sourced M25/A282 ring and its shared 40m support buffer now contain all nine airports and every mapped runway vertex, validated by the motorway tests. The original conflict remains recorded in project `airports/m25-boundary-check.json`.

Stapleford's operator Pilot Brief v1, dated 05 May 2026, page 3 and Appendix G (page 12), supersedes OSM's incorrect whole-runway asphalt tag. The full 21L/03R mapped centreline is grass, 46m wide. A separate 600m × 18m asphalt insert follows that centreline southwest from its mapped northeast end, using the operator's explicit Appendix G dimensions. The insert endpoint is calculated from the published length along OSM geometry, not a separately surveyed coordinate. Its grass continuation receives no asphalt runway markings. The archived PDF and rendered Appendix G are in project airport evidence. Parallel 21R/03L and cross-runway 10/28 remain grass. All pavement remains batched and terrain-draped.

Airport foundations now use the validated EA terrain corrections documented in `docs/airport-dtm.md`. The required airport DTM asset must be present before terrain creation and the shared bake.


## Kenley and Damyns Hall

[RAF2FTS identifies Kenley as an active satellite gliding site](https://www.raf.mod.uk/our-organisation/stations/raf-syerston/). The [Kenley Revival visitor guide](https://www.kenleyrevival.org/content/history/raf-kenley/1917-present/interactive-guide/interactive-visitors-guide) confirms the surviving crossing hard runways and perimeter track; none of the original hangars survive. Only the three current mapped campus buildings inside aerodrome way218499150 are modelled, all as support buildings without invented historical dates. Mapped12/30 and02/20 hard surfaces and07/25 grass remain distinct. Static training gliders have long unswept wings, narrow fuselages, canopies and central wheels, with no propeller or engine pods. Their dimensions and apron placements are illustrative.

[Damyns Hall's operator](https://www.damynshall.co.uk/flying_in) confirms three grass runways: main03/21 is650m;07/25 is480m and14/32 is400m for home-based aircraft. Two runway centrelines and two campus buildings come from OSM. The missing07/25 uses the labelled latitude/longitude graticule on the [Pooleys2020 chart](https://www.pooleys.com/media/9975/damyns-hall-egml_cropped.pdf), with published480m applied along its chart bearing. This approximation is explicitly identified in data and preparation code; it is not surveyed threshold geometry. Its western end extends outside the incomplete OSM aerodrome polygon, consistent with OSM also omitting this runway. The sourced runway remains inside the actual M25 ring and full-weight EA correction. Nearby Gerpins Farm features are excluded by campus filtering. Five light aircraft use authored grass parking beside mapped campus buildings, clear of runway corridors. Both additions have validated bounded EA bare-earth sources; see airport-dtm.md.

London City's Royal Albert and King George V dock context uses the separate exact wet-polygon helper documented in airport-docks.md. It does not scale with Structure or alter airport terrain anchors.

Final source verification command: `npx playwright test tests/airport-docks.spec.js tests/airports.spec.js tests/airport-dtm.spec.js --reporter=line`:16 passed in6.5s. Kenley retains all five connected mapped perimeter-taxiway ways, including northern arcs whose centroids fall outside the coarse aerodrome boundary; building suppression still uses only the three exact replacement footprints.
