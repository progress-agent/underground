# Reproducible Balloon measurement

Use `scripts/measure-balloon.mjs <out-dir> <live-origin> <new-origin>` under the shared GPU lock. It runs fresh real-GPU headless Chromium contexts, DPR 1, 4x main-thread CPU throttle, Automatic, a 60-second settle, then a 2.5-second FPS window, live/new interleaved three times. Keep all CDP sessions attached until the browser closes: detaching can reset throttling. Primary gate runs do not enable the CPU profiler; the separate diagnostic files retain their profiles.

The standard view explicitly resets the Balloon's third-person rig to yaw PI (south), pitch -0.12, zoom 1, at the existing Waterloo body placement. It previously inherited the prior camera heading, so running only Balloon and running the complete ten-view sequence could show different pictures. Output records the actual measured camera position and quaternion. Let the Balloon drift and sink as it does in play; use the same settle duration and view order for a comparison.

The October 16 harness used a 24-second settle; October 31 used 60 seconds. Re-running the original harness on its historical code and current production demonstrates the duration effect on both: the longer flight moves about 206 to 218 metres across the map and descends about 60 to 64 real metres. The southern heading is identical in these four runs. The historical 53.6 fps is an early-flight figure, rather than the later player view represented by the 60-second protocol. The exact old number is not reproduced on demand: current measurements of the historical code are 46.0 fps at 24 seconds and 19.5 fps at 60; current production measures 50.8 and 21.8 fps respectively. All use the same attached throttle. Do not compare different elapsed flights as a code regression.

A separate full-order production profile of the slow view measures 19.71 fps / 50.54 ms CPU, with 19.63 seconds of a 74.71-second sample under station-name occlusion. Those rays repeatedly traverse detailed landmark triangles after only a loose bounding-sphere rejection. Computing exact geometry bounding boxes in the same live page raises that expensive view to 53.8 fps. `Mesh.raycast` already uses a present box solely for exact rejection before its existing triangle test; no rendered geometry, lighting, figure, label policy or Automatic rung changes.

The fix computes those bounds when landmark pickables are registered. Structure height changes the containing anchor's scale, so geometry-local bounds remain valid. Final three-run figures, poses, source hashes and the frozen full-quality comparison belong in the sprint evidence. Retain the historical timing and heading diagnostics there as well: neither pose nor elapsed flight may be silently substituted.
